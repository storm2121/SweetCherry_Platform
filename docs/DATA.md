# Data

This repository contains no real market prices and no personal data. Every price in it comes from a simulation, and every file built from it says so.

## 1. Simulated market data

| | |
|---|---|
| File | `forecasting/samples/sweetcherry_market_data_SIMULATED_seed20260524.xlsx` |
| Provenance | `synthetic`: generated by `forecasting/sweetcherry_forecasting/synthetic.py`, generator version 1.0.0, seed 20260524 |
| Period | 2018-01-01 to 2026-05-24 (the data cutoff) |
| Content | Daily wholesale bulletin lines for cherries in Casablanca (M01), Rabat (M02) and Marrakech (M03), grades A, AA and AAA |
| Units | MAD/kg (wholesale) for prices; tonnes for arrivals |

The workbook has five sheets:
1. **Read me:** a SIMULATED DATA banner, plus provenance as key/value rows: `provenance`, `sourceName`, `generatorVersion`, `seed`, `periodStart`, `dataCutoff`, `generatedAt`, units and row counts.
2. **Data dictionary:** each column's type, unit and allowed values.
3. **Assumptions:** every simulation setting. It's written from `forecasting/sweetcherry_forecasting/config.py`, so the description cannot drift from the code.
4. **Simulated events:** the invented shocks (frost-like nights, bumper crops, rain at harvest, heat spells, transport-cost rises). **None of them happened, and none is a weather record.**
5. **Observations:** one line per date, market and grade, with min, modal and max price, arrivals, supply type (fresh, cold storage, import), main origin region, status, quality flag and remark.

**What the simulation assumes.** The values are illustrative, chosen to make the series behave like a fresh-produce market; they are not measured.
- **Harvest:** it climbs the Middle Atlas from about early May (Taounate, Sefrou) to late July (Ifrane). The whole season shifts a few days each year.
- **Price follows supply.** It is highest for the first fruit, lowest at the harvest peak, and moderate late in the season. Cold-stored fruit sells higher after the harvest, and counter-season imports appear from December to February.
- **Grades and markets:**
  - A ≈ 0.70 × AA and AAA ≈ 1.45 × AA. Premiums are wider when fruit is scarce.
  - Rabat runs 3–6% and Marrakech 5–9% above Casablanca. Prices drift about 2.5% a year in nominal terms.
- **Noise:**
  - one daily factor shared by all markets, plus a deviation per market;
  - more noise early and late in the season, and for AAA.
- **Recording imperfections:**
  - **Gaps and closures:** 5–12% of bulletins missing; markets closed on public holidays and for two days at Eid al-Adha (approximate dates).
  - **Rounding:** prices rounded to 0.5 MAD.
  - **Odd lines:** a few explained outliers (auction lot, rain-cracked lot, end-of-day clearance), each with a remark, and rare suspect entries (decimal slip, grade mix-up).

**Use it for** building, testing and demonstrating the forecasting code. **Do not use it for** pricing decisions, or as evidence of how real markets behave.

**Regenerate it:**

```bash
cd forecasting
python -m sweetcherry_forecasting generate --seed 20260524 --cutoff 2026-05-24
```

The same seed and generator version give the same lines, which `forecasting/tests/test_samples.py` checks against the committed file.

**Why the data is simulated.** An older market workbook from an earlier phase of the project has unknown provenance and no publication rights. It is not in this repository and was not used.

## 2. Forecast exports: contract v1

The admin dashboard's Excel upload, the JSON export and the demo importer all use this format.

**Workbook.**
- **Sheets:** `Grade A`, `Grade AA`, `Grade AAA`, then `About` last.
- **Grade sheets:** the first row is exactly `Date | Market | Low (P10) | Expected (P50) | High (P90) | Horizon Type | Horizon`.
- **Row rules:**
  - `Date` is the Monday of the target week, written as ISO text (`YYYY-MM-DD`) so no time zone can shift it.
  - `Market` is `M01`, `M02` or `M03`.
  - Prices are finite and non-negative, with Low ≤ Expected ≤ High.
  - `Horizon Type` is `short_term`, and `Horizon` runs from `1w` to `8w`, counted in weeks after the cutoff week.
  - Longer horizons are not part of v1.
- **About:** the first rows are machine-readable key/value pairs, with the key in column A and the value in column B:
  - `provenance` (`synthetic`), `dataCutoff`, `generatedAt` (ISO UTC timestamp);
  - `modelVersion`, `sourceName` (`Synthetic market simulation`), `seed`, `generatorVersion`;
  - descriptive rows: `notice`, `snapshot`, `units`, `horizons`, `markets`, `inputWorkbook`, `rowCounts`, `calibration`, `backtest`, `forecastNote`.

  A backtest table follows, labelled as computed on simulated data.

**JSON** (`schema: sweetcherry.forecastSheets.v1`):
- `about`: the same key/value pairs;
- `backtest`: the per-horizon and overall figures;
- `grades`: `{ "A": [rows], "AA": [rows], "AAA": [rows] }`, each row being `{ date, market, low, expected, high, horizonType, horizon }`.

**Firestore** (`forecastSheets/{A|AA|AAA}`): the admin upload (`src/utils/forecastWorkbook.js`) and the demo importer (`scripts/seed-forecast-demo.mjs`) store:
- `rows`, `rowCount`, `incompleteIntervalCount`, `updatedAt` and `uploadedBy`;
- the six machine-readable About values: `provenance`, `dataCutoff`, `generatedAt`, `modelVersion`, `sourceName`, `seed`.

That makes 11 fields; the security rules allow up to 20. All three grades are written in one batch. An upload that has an empty grade sheet, such as an off-season export, is refused rather than replacing a published forecast with nothing. The demo importer accepts only workbooks marked `provenance = synthetic`.

**Samples:**
- `forecasting/samples/sweetcherry_forecast_SIMULATED_2026-05-24.xlsx` and `.json`.
- The cutoff of 24 May 2026 falls just after the simulated 2026 season opens, and the rows cover the weeks starting 25 May to 13 July 2026.
- This is a fixed demonstration snapshot, not current market data.

The contract is enforced by:
- `src/utils/__tests__/forecastData.test.mjs`, which runs the sample through the same parsing and validator as an admin upload;
- `forecasting/tests/test_samples.py`.

## 3. Demo accounts and seed data

`tests/rules/seed-demo.mjs` fills the local Firebase emulators. It refuses to run against anything but `127.0.0.1` or `localhost`.
- **Accounts:** every account name says it is a demo account. Phone numbers are fictional (`+21260000000x`, `+966500000008`), and every account uses the password `demo-pass-1234`.
- **Photos:** none are shipped. A local folder of photos can be passed as an argument, and is never committed.
- **Forecasts:** the seed does not write any. `scripts/seed-forecast-demo.mjs` imports the simulated forecast sample.

- No production records, user accounts, phone numbers or photos are in the repository.
